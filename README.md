# Сайт Івана Куліка

Портфоліо художника: галерея олійного живопису, цикли робіт, блог і форми
замовлення. Next.js 16 (App Router), чистий JavaScript без TypeScript,
власні CSS-змінні без Tailwind, п'ять мов, світла й темна тема.

## Запуск

Потрібен Node.js 20.9+ (вимога Next.js 16) і npm.

    npm install
    cp .env.example .env.local   # далі заповнити змінні, див. нижче
    npm run dev                  # http://localhost:3000

Корінь `/` не має власної сторінки: `proxy.js` дивиться на `Accept-Language`
і редіректить на префікс мови — `/uk`, `/en`, `/pl`, `/de`, `/ru`. Для мов
поза цим списком запасна — англійська.

Інші команди:

    npm run build && npm start   # продакшн-збірка
    npm run lint                 # eslint (форматера й тестів у проєкті немає)

## Змінні оточення

Усі, крім `NEXT_PUBLIC_SITE_URL`, обов'язкові — без них не працюють пошта,
вхід в адмінку й підпис форм. Значень тут навмисно немає: локально вони
живуть у `.env.local` (він у `.gitignore`), на проді — у налаштуваннях
Netlify.

| Змінна | Призначення |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | Базова адреса сайту. Використовується для canonical, hreflang, Open Graph і абсолютних посилань у листах. Єдина змінна, що потрапляє в браузер. |
| `SESSION_SECRET` | Випадковий рядок від 32 символів. Підписує сесію адмінки і HMAC-токен публічних форм (`lib/formGuard.js`). |
| `ADMIN_USERS` | JSON-масив `[{"login","name","hash"}]` — акаунти адмінки. `hash` це bcrypt (cost 12), згенерувати: `node scripts/hash-password.mjs "пароль"`. |
| `RESEND_API_KEY` | Ключ Resend. Без нього лист не відправляється, а заявка повертає помилку — тобто на проді він обов'язковий. |
| `MAIL_FROM` | Адреса відправника. Домен має бути верифікований у Resend. |
| `MAIL_TO_ADMIN` | Куди йдуть службові листи: вхід з нового пристрою, блокування підбору пароля. |
| `MAIL_TO_INQUIRY` | Куди йдуть заявки з форм. Якщо не задано — використовується `MAIL_TO_ADMIN`. |
| `BLOB_READ_WRITE_TOKEN` | Необов'язкова. Вмикає драйвер Vercel Blob (див. «Сховище»). На Netlify не потрібна. |

`NETLIFY` та `IS_NETLIFY_BUILD` виставляє сама платформа під час збірки —
руками їх задавати не треба.

Важливо для `.env.local`: у bcrypt-хешах усередині `ADMIN_USERS` кожен `$`
треба екранувати як `\$` (`\$2b\$12\$...`). Інакше `dotenv-expand` усередині
`@next/env` вважає `$word` підстановкою змінної й тихо псує хеш. На проді
цього не потрібно — Netlify передає значення напряму в `process.env`.

## Структура

    app/(site)/[locale]/   публічні сторінки: головна, живопис, цикли,
                           блог, про мене, контакти
    app/(admin)/admin/     адмінка
    app/api/               маршрути: заявки, вхід, вивантаження файлів
    components/            React-компоненти сторінок
    lib/                   спільна логіка: сховище, пошта, авторизація,
                           rate-limit, захист форм, SEO, i18n
    data/site.js           контент за замовчуванням: роботи, цикли, контакти
    dictionaries/*.json    переклади інтерфейсу, п'ять файлів
    blog-content/<lang>/   статті блогу у форматі .mdx, окремий файл на мову
    content/               локальне рантайм-сховище, у git не потрапляє
    docs/audit/            звіти аудитів (SEO, анімації, UI, посилання)
    scripts/               допоміжні скрипти (генерація bcrypt-хеша)
    proxy.js               визначення мови й редірект з `/`

Коментарі в коді — українською, ідентифікатори — англійською.

## Адмінка

`/admin`, вхід за логіном і паролем з `ADMIN_USERS`. Розділи: картини (олія),
цикли, автентичність, блог, головна, «про мене», контакти. Через неї
редагується вміст, що лежить у сховищі, і завантажуються зображення.

Тексти статей блогу адмінка не редагує — вони лежать у `blog-content/` як
`.mdx` і правляться в репозиторії. З адмінки задаються лише обкладинки.

Що працює довкола входу:

- обмеження спроб входу з IP і лист на `MAIL_TO_ADMIN` у момент блокування;
- лист про вхід з нового пристрою (`lib/deviceTracking.js`);
- журнал подій — `/admin/logs`, пише `lib/auditLog.js`;
- порівняння пароля в постійний час, щоб час відповіді не виказував,
  чи існує акаунт.

Завантаження зображень: не більше 15 МБ, тип перевіряється за магічними
байтами, а не за розширенням; кожен файл переганяється через `sharp` —
поворот за EXIF, вписування в 2500×2500 і конвертація у WebP.

## Сховище

Бази даних немає. `lib/store.js` вибирає драйвер під час виконання:

1. **Netlify Blobs** — на збірках Netlify, основний варіант;
2. **Vercel Blob** — якщо задано `BLOB_READ_WRITE_TOKEN`;
3. **файлова система** — каталог `content/`, запасний варіант для розробки.

Той самий драйвер використовують журнал подій, лічильники rate-limit і
відбитки відомих пристроїв. Каталог `content/` цілком у `.gitignore`:
на проді дані живуть у блобах, локальна копія — робоча.

## Перенесення даних між локальним і продом

Дані сайту (роботи, ціни, тексти, контакти, обкладинки) не лежать у git:
локально це `content/data.json`, на проді — Netlify Blobs. Два скрипти
переносять їх в обидва боки.

Обом потрібні `NETLIFY_SITE_ID` і `NETLIFY_AUTH_TOKEN`:

- **Site ID** — Netlify → сайт → Site configuration → General → Site
  information → рядок «Site ID».
- **Personal access token** — Netlify → аватар → User settings →
  Applications → Personal access tokens → New access token. Значення
  показують один раз.

Передавати їх краще змінними оточення, а не аргументами: аргументи
осідають в історії оболонки й видні в списку процесів. Скрипти токен
не друкують.

### Забрати з проду

    NETLIFY_SITE_ID=... NETLIFY_AUTH_TOKEN=... node scripts/pull-data.mjs

Читає Blobs і кладе копію в `content/backups/data-РРРР-ММ-ДД-ГГХХСС.json`.
Поверх `content/data.json` не пише ніколи — локальна робота лишається
недоторканою. Потрібен, щоб зробити копію перед заливкою і щоб забрати
те, що художник наредагував в адмінці.

### Залити на прод

    NETLIFY_SITE_ID=... NETLIFY_AUTH_TOKEN=... node scripts/push-data.mjs

Перевіряє `content/data.json` тими самими правилами, що й адмінка
(`lib/siteData.mjs`), показує, що лежить на проді зараз і що поїде
натомість, і лише тоді питає підтвердження з клавіатури. Прод
перезаписується цілком, тож спершу зробіть копію через `pull-data`.

- `--dry-run` — усе, крім запису.
- `--confirm` — без запитання (для випадків, коли ви точно знаєте, що
  робите).

Сторінки оновляться протягом хвилини: у них `revalidate = 60`.

Основна платформа — **Netlify** (`netlify.toml`). `vercel.json` лишається
другою ціллю; Vercel Blob при цьому доступний і як драйвер сховища.

Перед першим деплоєм: задати всі змінні оточення з таблиці вище, підключити
домен і верифікувати його в Resend, інакше листи не підуть.

`sharp` має лишатися в `serverExternalPackages` у `next.config.mjs` і в
`external_node_modules` у `netlify.toml` — це нативний модуль, збірка в бандл
його ламає. Заголовки безпеки задаються в `headers()` у `next.config.mjs`,
не в `netlify.toml`.
