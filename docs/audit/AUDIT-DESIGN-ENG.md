## Разбор по темам задания

### Состояния кнопок

**`:active` нет нигде.** Проверено grep'ом по всему `globals.css` — ноль вхождений.
Это первый пункт раздела «Component Building Principles» в скилле:
«Add `transform: scale(0.97)` on `:active`. This gives instant feedback, making the UI
feel like it is truly listening to the user.» Затронуты `.btn-hero` (370),
`.header-cta` (211), `.btn-primary` (1190), `.btn-secondary` (1198),
`.form button[type=submit]` (643), `.works-filter` (1251), `.filter button` (511),
`.burger` (293), `.modal-close` (630), `.scroll-top` (696), `.sound-btn` (732).

На сенсорном экране это заметнее всего: hover там не работает по определению
(и правильно гейтирован через `@media (hover: hover)`), а `:active` — единственный
способ подтвердить касание. Сейчас на телефоне ни одна кнопка сайта не реагирует
на палец.

**`:disabled` не стилизован.** Ноль вхождений `disabled` в CSS. Единственная
disabled-кнопка на сайте — отправка формы (`OrderForm.js:99`) — во время запроса
выглядит ровно как активная, и `cursor: pointer` из `globals.css:134` на ней остаётся.

**hover: есть, но с тремя дырами.**

1. *Специфичность.* `a:hover` (globals.css:127) имеет ту же вес (0,1,1), что
   `.langs a` (291), `.works-foot a` (1369) и `.blog-toc nav a` (1548). Все три
   объявлены позже — и выигрывают. Переключатель языка (пять целей в шапке и в меню),
   ссылка «Переглянути всі картини» под сеткой работ и пункты оглавления статьи
   на наведение не отвечают.
   Обратная сторона той же медали: `.cycle-title-link { color: inherit }` (917)
   имеет вес (0,1,0) — ниже `a:hover`, поэтому название цикла на главной **всё-таки**
   становится охряным при наведении, хотя комментарий на 915-916 объясняет, что
   это «заголовок, а не акцентне посилання». Правило проигрывает собственному
   намерению.

2. *`<button class="link">`.* `.link` (176) задаёт только `text-decoration`.
   Цвет и hover ссылки живут в `a { }` (122-127) — селектор по тегу, к кнопке не
   применяется. Значит `Gallery.js:131` («Придбати» / «Запитати ціну» в каждой
   карточке), `:178` (то же в просмотрщике), `:141`, `:187-188`, `:195` — подчёркнутый
   текст цвета абзаца, без цвета акцента и без реакции на курсор. При этом
   `OrderForm.js:110,114` использует `<a class="link">` и всё получает правильно.
   Один класс `.link` ведёт себя по-разному на двух тегах.

3. *Пропущенные элементы.* `.viewer-nums button` (548-549), `.burger` (293),
   `.modal-close` (630), кнопка «Закрити» в мобильном меню (`Header.js:136`) —
   hover-состояния нет вообще.

**focus.** Единственный осознанный `:focus-visible` в проекте — на кнопке звука
(`globals.css:742`, `outline: 2px solid #fff; outline-offset: 2px`). Сделано хорошо
и ровно так, как надо. Проблема в том, что это единственный случай.

### Обратная связь на действия

Разобрано по каждому действию, доступному посетителю:

| Действие | Обратная связь сейчас |
| --- | --- |
| Нажатие любой кнопки | нет (`:active` отсутствует) |
| Отправка формы | кнопка блокируется, но не меняется; спиннера нет |
| Успешная отправка | форма мгновенно заменяется абзацем |
| Ошибка формы | текст появляется в конце формы, мгновенно |
| Поиск по номеру, успех | адрес меняется, галерея перерисовывается — без перехода |
| Поиск по номеру, ошибка | сообщение появляется мгновенно, сдвигая футер (`globals.css:608`, `flex-basis: 100%`) |
| Смена фильтра работ | сетка мгновенно другая |
| Клик по миниатюре | просмотрщик появляется, страница не двигается |
| Переход из поиска в просмотрщик | появляется + плавный скролл (`Gallery.js:57`) — не как в предыдущей строке |
| Смена темы | фон щёлкает, шапка доезжает за 240ms, ссылки за 150ms |
| Кнопка звука на видео | ✓ меняется эмодзи, подпись и `aria-pressed` |
| Наведение на карточку работы | ✓ масштаб + охряная риска |
| Копирование номера работы | `user-select: all` ✓, но подтверждения нет |

Строк с «нет» больше, чем со «✓». Из них по-настоящему дорого стоят две:
отправка формы (единственный канал продажи) и смена фильтра.

### Состояния загрузки

- **Изображения**: все контейнеры имеют `background: var(--bg-deep)`
  (`globals.css:454, 543, 554, 632, 875, 1021, 1062, 1139, 1300, 1416`) — то есть
  вместо белой дыры тёмный прямоугольник нужной пропорции. Это минимум, и он
  выполнен последовательно. `placeholder="blur"` не используется ни разу.
- **Пропорция известна заранее** — `WorksSection.js:17-24` берёт `aspect-ratio`
  из размера холста, а не из файла. Сетка не прыгает при подгрузке. Это сильное
  решение, отмечаю.
- **Форма**: `OrderForm.js:17-22` тянет токен в фоне и молча; если он не успел —
  добирает при сабмите (`:35-41`). Обработано аккуратно, посетитель ничего не замечает.
  Ровно то, что скилл называет «handle edge cases invisibly».
- **Навигация**: `loading.js` нет ни у одного маршрута. Для статики с `revalidate: 60`
  это почти незаметно, для `/blog/[slug]` с рендером MDX — заметнее.
- **Кнопка отправки**: нет ни спиннера, ни `…` в подписи. Скилл отдельно отмечает,
  что быстрый спиннер делает ожидание субъективно короче; здесь ожидание никак
  не обозначено.

### Обработка ошибок форм

Разделение кодов ошибок на «виноват ввод» и «виновата система»
(`OrderForm.js:8`, `INPUT_ERROR_CODES`) с показом запасного контакта только во втором
случае — это правильная мысль, и она прокомментирована (строки 4-7). Тексты ошибок
содержат действие, а не только констатацию («Заповніть ім'я та email»,
«Спробуйте пізніше») — требование «Error messages include fix/next step» выполнено.

Что не так: сообщение стоит одно на всю форму, в самом низу, после кнопки и после
строки «відповім протягом дня». Поле, вызвавшее ошибку, никак не помечено, фокус
не переносится. То есть диагноз верный, а адресован он не туда.

Плюс: `pattern` на email (`:86`) и телефоне (`:90`) даёт браузерную валидацию —
но её сообщения не стилизованы и приходят на языке браузера, а не страницы.
Смешение двух систем сообщений об ошибке в одной форме.

### Плавность переходов между состояниями

Полностью разобрано в `AUDIT-ANIMATIONS.md`. Здесь фиксирую только вывод с точки
зрения ощущения продукта: **на сайте нет ни одного перехода между состояниями
интерфейса.** Все анимации, которые есть, — это либо появление при загрузке
(`riseIn`), либо hover, либо декоративные пульсы. Каждое изменение, вызванное
действием посетителя — фильтр, модалка, меню, галерея, тема, результат формы —
происходит подменой.

11. `Gallery.js:56` — проверка `prefers-reduced-motion` перед `scrollIntoView`,
    потому что JS-скролл не подчиняется CSS.
12. `layout.js:69-80` — тема ставится до первой отрисовки, `prefers-color-scheme`
    осознанно игнорируется, решение объяснено.

Двенадцать против семи. По плотности внимания к невидимому этот код заметно выше
среднего — и именно поэтому его слабые места сосредоточены не в мелочах, а в
крупном: состояниях кнопок и переходах между состояниями интерфейса.

## Что из скилла неприменимо

- **Springs, drag-with-momentum, `useSpring`** — Framer Motion / Motion в проекте нет
  (`package.json` не содержит), и вводить его ради существующих задач незачем.
  Единственный жест на сайте — свайп в просмотрщике; его разбор в
  `AUDIT-ANIMATIONS.md`.
- **`transform-origin` для поповеров** — анкоренных к триггеру поповеров, дропдаунов,
  тултипов и селектов на публичной части нет. Модалка центрирована, для неё центр
  правилен по умолчанию.
- **Тултипы с пропуском задержки на соседних** — тултипов нет.
- **`clip-path` (hold-to-delete, comparison slider, tab indicator)** — деструктивных
  действий с подтверждением удержанием и табов на сайте нет.
- **3D-трансформы, орбиты** — нет и не нужны: заявленная эстетика
  (`CLAUDE.md`, раздел Design) прямо противоположна.
- **Принципы Sonner (DX библиотеки, документация, нейминг пакета)** — раздел про
  разработку публикуемых компонентов, к сайту-витрине не относится.
